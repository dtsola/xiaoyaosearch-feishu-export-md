# 精简MRD：小遥搜索飞书导出工具

## 1. 核心问题（一句话）

飞书用户无法方便地将文档/知识库导出为本地Markdown格式，缺乏跨平台的命令行导出工具。

## 2. 目标用户（具体画像）

### 个人用户
- **人群特征**：知识管理爱好者、自由职业者、学生
- **痛点场景**：
  - 想要备份自己的飞书文档到本地
  - 需要将飞书内容迁移到其他笔记工具（Obsidian、Logseq等）
  - 担心云端数据安全，希望有本地备份
- **当前替代方案**：手动复制粘贴、使用浏览器插件、放弃导出

### 企业/团队用户
- **人群特征**：创业团队、知识库管理员、IT运维人员
- **痛点场景**：
  - 需要批量导出大量文档进行归档
  - 知识库迁移需求（如从飞书迁移到其他平台）
  - 定期备份企业知识资产
- **当前替代方案**：人工逐个导出、使用飞书企业版导出功能（有限制）

### 开发者
- **人群特征**：技术文档维护者、DevOps工程师、独立开发者
- **痛点场景**：
  - 需要将文档导出集成到CI/CD流程
  - 技术文档的版本控制需求
  - 自动化备份需求
- **当前替代方案**：自己写脚本调用飞书API（开发成本高）

## 3. 解决方案（核心功能）

**MVP三个核心功能：**

1. **命令行配置管理**
   - 支持飞书API密钥配置
   - 支持导出路径、格式等参数配置
   - 配置持久化，避免重复输入

2. **批量文档导出**
   - 支持按文件夹批量导出
   - 支持指定文档ID列表导出
   - 保留文档层级结构

3. **知识库导出**
   - 单个知识库完整导出
   - 保留知识库的目录结构
   - 支持图片、附件等资源的处理

## 4. 竞品情况

| 竞品 | 优势 | 劣势 | 差异化机会 |
|------|------|------|-----------|
| 飞书官方导出 | 官方支持，格式完整 | 仅Web端手动操作，无批量处理，无命令行 | 跨平台CLI、批量自动化 |
| 浏览器插件 | 安装简单 | 依赖浏览器，无法批量自动化，跨平台差 | 命令行可集成到工作流 |
| Python脚本 | 灵活可定制 | 需要编程能力，维护成本高 | 开箱即用，用户友好 |
| 其他第三方工具 | 功能完整 | 可能收费，闭源，安全性存疑 | 完全开源免费 |

## 5. 商业模式

- **变现方式**：完全免费开源，通过GitHub社区维护
- **预估成本**：
  - 开发成本：约40-60小时（MVP）
  - 运营成本：文档托管（GitHub Pages）、域名（可选）
- **预估收入**：
  - 无直接收入
  - 间接收益：小遥搜索品牌曝光、开发者社区影响力

## 6. 风险评估

- **技术风险**：
  - 飞书API可能变更，需要持续维护
  - 跨平台兼容性问题（Windows、macOS、Linux）
  - 大量文档导出可能触发API限流

- **市场风险**：
  - 飞书官方可能推出类似功能
  - 用户需求可能不足（飞书用户可能不需要本地导出）
  - 其他文档平台的竞争

- **时间风险**：
  - 依赖飞书开放平台的API稳定性
  - 首次开发可能需要调试API调用
